# 分享笔记与导入（0.2.0）

面向同一项目的不同目录、不同电脑及修改过的代码版本。接收方需要自行取得代码；分享文件只包含笔记和少量定位上下文。

## 导出

在 Reading Notes 工具栏点击“分享笔记：导入 / 导出”按钮，选择导出全部，或先选中一个主题、分组、笔记，再选择导出所选项。树节点右键菜单也提供“导出所选项”。保存为 `.readingnotes.json`。

文件包含主题分组、笔记 ID、标题、正文、创建/修改时间、相对文件路径、原行号，以及绑定行和前后各 3 行代码。还会保存文件内容指纹，以判断源码是否完全一致。不会附带完整源文件，也不会自动写入发送方电脑的绝对文件路径。正文和源码片段仍可能包含用户自己写入的信息，导出前应检查是否适合分享。

项目外文件使用 `external/文件名` 作为占位路径，接收方必须显式映射。无法读取源码的笔记仍会导出，保留已有上下文并提示接收方确认位置。

## 导入

1. 在接收方项目中打开 Reading Notes，选择“导入分享文件”。
2. 选择当前项目中的代码根目录。默认是当前项目根目录。
3. 查看“笔记预览”。文件完全一致，或代码与上下文唯一可靠匹配时，会自动选中位置。代码已改写、存在多个相似位置、已失效的锚点，以及修改过文件中的空行，保留待确认。
4. 文件改名或目录变化时，切到“文件路径映射”。可以编辑目标相对路径、选择新文件或批量替换目录前缀，然后点击“重新匹配”。
5. 对待确认位置，查看原代码与当前代码，选择候选或输入行号，点击“采用此行”。无法定位的笔记也可先导入为“位置待确认”，之后使用“绑定到当前行”。
6. 点击表格中的“导入处理”选择合并方式。同 ID 且内容和绑定相同的笔记默认跳过；冲突可选择跳过、替换当前、保留两条。保留两条会给副本分配新 ID。
7. 确认合并导入。提交前会重新核对源码；预览之后笔记有其他修改时，会要求重新预览。

同名主题会合并，同一主题下的同名分组会合并。导入不会修改代码文件。文件缺失或定位失败不会删除正文。

## 备份与恢复

每次合并前，在当前项目的 `.idea/reading-notes-backups/` 中创建独立 XML 备份。备份保存导入前完整笔记，不经过分享文件的路径转换；不要把本机备份当作脱敏分享文件发送。

恢复时先关闭项目，另存当前 `.idea/reading-notes.xml`，再把选中的备份复制到该路径并重新打开项目。备份不会自动清理，可以自行归档。

0.2.0 继续读取旧 XML。保存时新增可选的 `utf8Payload` 字段，防止 IDE XML 写入丢失表情等补充 Unicode 字符；该字段优先用于恢复完整数据。不要手动只编辑 XML 中的可读字段，否则可能被完整数据字段覆盖。

## 边界

- 支持 Reading Notes 自身的分享格式（版本 1），不是其他插件的数据导入器。
- 无需 Git，也不会检出分支、修改或自动下载源码。大规模重写可能仍需手动绑定。
- 分享文件上限 16 MB，最多 5,000 条笔记；单个自动读取的源码文件上限 4 MB。请按主题或分组拆分大型分享。
- 拒绝绝对路径、目录穿越及指向所选目录之外的文件链接。
- JSON 由插件保存到本机；实际发送给别人的动作由用户自行完成，没有云同步或上传服务。
